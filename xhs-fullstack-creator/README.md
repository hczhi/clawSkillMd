## 🔄 五步创作流程详解

### Phase 1: 选题发散器 🧠
**输入**: 模糊想法 ("我想发装修相关的内容")
**处理**: 
- 应用 MrBeast CTR×AVD 双轮评估
- STEPPS 六维打分 (Social Currency, Triggers, Emotion...)
**输出**: 3-5 个高潜力选题 + 评分排名

**示例**:
```
1. "水电改造避坑：8 千变 1 万 4 的真相" (STEPPS: 26/30)
2. "程序员用 Python 监控水电预算" (STEPPS: 24/30)
3. "水电验收 7 大节点" (STEPPS: 23/30)
```

---

### Phase 2: 深度洞察提炼 🔍
**输入**: 选定选题方向
**处理**: 四次追问
1. 模式识别："你和常规做法有什么不同？"
2. 悖论挖掘："哪里反直觉但有效？"
3. 概念命名："这个你没说过的方法叫什么？"
4. 对比创造："模仿者会失去什么核心优势？"
**输出**: 你的独特定位主张

**示例**:
```
你的定位：不是"教水电知识",而是"程序员的预算监控系统"
悖论发现：越暴露问题 → 越获得信任
未命名概念："透明化决策路径"
建议表述：@程序员小智 - 用数据说话的真实装修日记
```

---

### Phase 3: 内容框架设计 📐
**输入**: 选定的主题和定位
**处理**: MrBeast 阶梯递进公式
**输出**: P1-P2 → P3-P4 → P5 → P6 完整大纲

**示例**:
```
P1 封面："128,750 元！我的装修账单公开"
P2 悬念："但这还不是最坑的..."
P3 干货 1: 硬装费用 breakdown(占比 65%)
P4 干货 2: 最容易超支的 3 个隐藏项
P5 反转："最大冤种是这笔 2000 元的"
P6 CTA: "关注→明天揭晓答案"
```

---

### Phase 4: 文案生成与润色 ✍️
**输入**: 内容大纲
**处理**:
- pain-point-copywriting 卖点转化术
- anti-ai-cheatsheet 人类化检查
**输出**: 自然真实的发布级文案

**示例**:
```
宝子们！！今天我终于把装修账单整理好了😭

整整 128,750 元啊！！！当初说好的 10 万预算直接超了 2 万多...

💸 **冤种排名 NO.1**: 全屋定制
销售说"套餐包含所有五金"...

[更多正文...]

✅ Emoji 密度：2.1% (>1.5% threshold)
✅ 第一人称频率：>3 次/100 字
✅ AI 特征词检测：通过
```

---

### Phase 5: 质量审核优化 🔍
**输入**: 初稿文案
**处理**:
- Persona consistency checklist (@程序员小智四维度)
- Data validation rules (防幻觉规范)
- MrBeast pacing check
**输出**: 最终发布方案 + 改进建议

**示例**:
```
👤 人设一致性评分：78/100

维度分解:
• Programmer Perspective: 70/100 ×35% = 24.5
• Novice Perspective: 85/100 ×30% = 25.5  
• AI Enthusiast Perspective: 40/100 ×20% = 8
• Tone Consistency: 90/100 ×15% = 13.5

⚠️ 改进建议:
1. 加入"我用 Excel 做了个自动计算表"的情节
2. P5 悬念可以更具体
3. 添加数据可视化描述

✅ 数据验证：无编造预测
✅ MrBeast 节奏：前 30 秒抓眼球✓ 零无聊时刻✓
```

## 💡 最佳实践

### ✅ DO
- 初期想法越模糊越好 ("随便聊聊装修"就能开始)
- 随时打断并要求切换方向 ("跳过这个""换方向")
- 给真实反馈 ("太 AI 了""这句很奇怪")
- 善用反问让系统问你问题

### ❌ DON'T
- 一次性要求全部完成 (会被当机器人生成器)
- 忽略用户的实时调整信号
- 接受没有置信度的数据预测
- 默认所有内容都完美 (保持迭代思维)

## 🔧 技术实现

本 skill 通过以下方式整合多个 skill 的能力:

```python
# 伪代码逻辑
def execute_fullstack_flow(user_input):
    phase1_output = brainstorm_phase(user_input)      # 调用 brainstorm skill 逻辑
    phase2_output = deep_dive_phase(phase1_output)    # 调用 creative-thought-partner 逻辑
    phase3_output = structure_phase(phase2_output)    # 调用 mrbeast-skill 逻辑
    phase4_output = writing_phase(phase3_output)      # 调用 humanizer 逻辑
    phase5_output = review_phase(phase4_output)       # 调用 xhs-operator-v2 逻辑
    
    return final_package(phase1-output, ..., phase5_output)
```

关键原则: **每个 phase 只处理该阶段的任务**,保持对话流畅性而非批量输出。
