# 小红书全栈创作系统 XHS Fullstack Creator

## 核心理念

**将 5 大 skill 有机融合，打造一条内容生产线**。

当用户只有模糊的想法（如"我想发篇装修预算的文章"），而不是完整的文案时，启动此 skill 进行端到端的内容创作支持。

---

## 🔄 五步创作工作流

### **Phase 1: 选题发散器 (Brainstorm)**
**目标**: 从模糊想法中挖掘高潜力选题方向

**执行步骤**:
1. **理解用户意图** - "你想做什么？装修日记？避坑指南？好物分享？"
2. **应用 MrBeast 原则** - CTR×AVD 双轮驱动评估
   - 标题是否够抓眼球？(0-10 分)
   - 内容是否有持续吸引力？(0-10 分)
3. **应用 STEPPS 框架** - 六维打分 (每维 1-5 分)
   - **Social Currency** 社交货币：会让人想转发吗？
   - **Triggers** 触发器：会触发日常联想吗？
   - **Emotion** 情绪：激发强烈情绪吗？
   - **Public** 可见性：容易被看到吗？
   - **Practical Value** 实用价值：有用吗？
   - **Stories** 故事：有叙事空间吗？
4. **输出结果**:
   ```markdown
   ### 推荐选题 (按评分排序)
   
   1. "装修预算公开：128,750 元明细表" 
      - STEPPS 总分：24/30
      - 优势：数据锚定+实用性+社交炫耀
      - 风险：需准备详细账单支撑
   
   2. "小白装修翻车实录：这 3 个坑我踩了"
      - STEPPS 总分：22/30
      - 优势：情绪共鸣+避坑价值
      - 风险：需真实案例配合
   
   3. "程序员如何用 Python 算装修预算"
      - STEPPS 总分：21/30
      - 优势：人设契合+工具派
      - 风险：受众较垂直
   ```

### **Phase 2: 深度洞察提炼 (Creative Thought Partner)**
**目标**: 找到你的独特定位和突破性洞察

**执行问题清单** (每次只问 1 个问题):
1. **模式识别**: "大多数人做装修博主都在晒成果，你选择公开失败经历。为什么这对你特别重要？"
2. **悖论挖掘**: "你说越展示困难越有人看，这和'只晒美好'的平台常规相反。为什么？"
3. **概念命名**: "你在用 Python 分析装修数据，这和普通博主的'经验总结'有什么本质不同？"
4. **对比创造**: "如果别人完全复制你的数据公开做法但不懂编程，他们会失去什么？"

**输出格式**:
```markdown
### 🔍 突破性洞察发现

**你的独特定位**: "数据派装修日记" vs 普通"经验分享派"

**核心悖论**: 越真实暴露问题 → 越获得信任
- 普通博主：晒精美效果 → 吸引羡慕 → 互动短暂
- 你：晒失败细节 → 引发共情 → 深度收藏

**未命名的概念**: "透明化决策路径"
- 不是只给结果（花了多少钱）
- 而是展示过程（为什么这么花、怎么砍价、如何比较）
- 这是其他博主没有的"程序员式思考"

**建议的定位表述**: 
"@程序员小智 - 用数据说话的真实装修日记"
标签：#数据派 #避坑指南 #透明化决策
```

### **Phase 3: 内容框架设计 (MrBeast Principles)**
**目标**: 设计零无聊时刻的内容结构

**MrBeast 六大法则应用**:

#### **法则 1: 前 30 秒决定生死**
```
P1 (封面页): 
- Hook 句："我花了 128,750 元装修，最后才发现 3 个大冤种支出"
- 视觉：数字放大 + 账单截图拼图
```

#### **法则 2: 阶梯递进原则**
```
P1-P2: 抓眼球 → 悬念建立
P3-P4: 给干货 → 具体案例分析
P5: 留悬念 → "还有更离谱的一笔..."
P6: 促行动 → "关注我，明天拆解第二笔"
```

#### **法则 3: CTR×AVD 双轮驱动**
- **CTR 优化**: 封面数字必须足够大、足够醒目
- **AVD 优化**: 每 3-4 页一个小反转/新信息点

#### **Output - 完整大纲**:
```markdown
## 📐 内容结构

| 页码 | 类型 | 内容 | Hook 技巧 |
|------|------|------|----------|
| P1 | 封面 | "128,750 元！我的装修账单公开" | 数字冲击 |
| P2 | 悬念 | "但这还不是最坑的..." | 反预期 |
| P3 | 干货 1 | 硬装费用 breakdown (占比 65%) | 数据可视化 |
| P4 | 干货 2 | 最容易超支的 3 个隐藏项 | 避坑预警 |
| P5 | 反转 | "最大冤种是这笔 2000 元的" | 悬念延续 |
| P6 | CTA | "关注→明天揭晓答案" | 钩子设置 |
```

### **Phase 4: 文案生成与润色 (Humanizer)**
**目标**: 生成自然真实的文案，消除 AI 味

**写作策略**:

#### **卖点转化术** (pain-point-copywriting.md):
| 专业术语 | 翻译成"她受的罪" |
|---------|-----------------|
| 瓷砖通铺工艺 | "贴错一块就要全部铲掉重来的绝望" |
| 全屋定制价格 | "销售说的'包含五金'其实是空欢喜一场" |
| 乳胶漆环保等级 | "闻着味道不敢住半个月的心惊肉跳" |
| 电路改造报价 | "本来以为省 3000，结果被多收了 8000" |

#### **人类化写作检查清单** (anti-ai-cheatsheet.md):
```
✅ Emoji 密度 > 1.5% (每 100 字至少 1-2 个)
✅ 第一人称频率 "我" 出现率 > 3 次/100 字
✅ 口语化表达 "说实话""真的绝了" 等
✅ 适度瑕疵 "当时我真傻了""现在想起来都想锤自己"
❌ 避免 AI 特征词：总而言之、综上所述、值得注意的是
❌ 避免过度工整：不要每个段落都是完美的"观点 + 论据"结构
```

#### **8 种风格模板**:
1. **碎碎念体**: "今天又踩雷了...真的心态崩了"
2. **数据控体**: "计算了一下，这 3 项花了 XXX 元"
3. **吐槽体**: "有没有人跟我一样被装修公司坑惨了"
4. **干货体**: "记住这 5 个点，少花 3 万块"
5. **故事体**: "那天发生的事到现在我还记得"
6. **清单体**: "我总结了 XX 个装修避坑要点"
7. **对比体**: "别人家 vs 我家，差距在哪里"
8. **提问体**: "你们遇到过这种情况吗？"

**Output - 初稿**:
```markdown
## 📝 正文初稿 (碎碎念体 + 数据控)

宝子们！！今天我终于把装修账单整理好了😭

整整 128,750 元啊！！！当初说好的 10 万预算直接超了 2 万多...

💸 **冤种排名 NO.1**: 全屋定制
销售说"套餐包含所有五金"，结果安装时说"阻尼铰链要加钱"
一算下来多加了 3,800 元...这谁顶得住啊😤

💸 **NO.2**: 水电改造
本来找了 3 家比价，最低报价 8,500
结果师傅进场后说"这里要改动，那里要增加"
最后结账：14,200 元...心在滴血💔

💸 **NO.3**: 美缝
自己买材料 + 请师傅 DIY = 2,300 元
后来才知道直接让装修公司全包只要 1,800...又被坑了500

⚠️ 血泪教训：
1. 签合同一定要写清楚"无增项"
2. 水电改造最好有人在现场盯着
3. 美缝可以自己买材料省一笔

后续还有更多账单明细，关注我别错过！下期拆解决策过程✨

#装修避坑 #装修账单 #装修日记 #我的装修记录 #省钱攻略
```

### **Phase 5: 质量审核优化 (Reviewer)**
**目标**: 确保符合@程序员小智人设标准

**审核维度**:

#### **A. 人设一致性检查** (persona-consistency-checklist.md):
```
[ ] ✅ 程序员视角 (+35%): 是否包含数据分析/工具推荐/Excel 相关内容
[ ] ✅ 装修小白视角 (+30%): 是否展现真实失败经历/情绪波动
[ ] ✅ AI 爱好者视角 (+20%): 是否提及自动化方案/AI+ 装修应用
[ ] ✅ 语调一致性 (+15%): Emoji 密度>1.5% / 口语化 / 个性化口头禅

当前稿件评分：__/100
改进建议：加入"我用 Excel 做了个自动计算表"的情节
```

#### **B. 防幻觉校验** (data-validation-rules.md):
```
❌ 严禁编造精确数字预测 ("预计 52,847 次曝光")
✅ 只提供保守区间 ("预计 3k-8k 曝光")
✅ 必须标注置信度和假设条件
✅ 宁可不说，不说假话

当前稿件数据核查：
- "128,750 元" → 可验证 ✓ (真实账单)
- "超了 2 万多" → 保守说法 ✓ (实际超 28,750)
- "3 家比价" → 可验证 ✓
- "后续曝光预测" → 无预测 ✓
```

#### **C. MrBeast 节奏检测**:
```
[ ] 前 30 秒 (P1-P2): Hook 足够有力？
[ ] P3-P4: 干货密度够不够？有无"无聊时刻"？
[ ] P5: 悬念是否让人想看下一集？
[ ] P6: CTA 是否清晰有力？

改进建议：P5 的"更有坑"可以改成"这笔 2000 元的花费是我今年最后悔的决定"
```

**Final Output - 发布级方案**:

## ⚠️ 关键约束

### **DO**:
- ✅ 每阶段只输出该阶段的结果
- ✅ 保持对话流畅，一次问一个问题
- ✅ 允许用户随时打断并要求切换方向
- ✅ 数据预测必须标注置信度和假设条件
- ✅ 强调"卖生活不卖参数"

### **DON'T**:
- ❌ 一次性输出所有内容 (会变成机器人生成器)
- ❌ 忽视用户的实时反馈
- ❌ 编造精确数字预测
- ❌ 使用 AI 特征词 ("综上所述""总的来说")
- ❌ 违背@程序员小智的人设定位

## 🚀 实战示例

### 示例 1: 完整的五步流程

**用户输入**: "我想发一篇关于装修水电改造的笔记"

**Phase 1 输出**:
```
根据你的需求，我给出 3 个选题方向：

1. "水电改造避坑指南：8 千变 1 万 4 的真相" (STEPPS: 26/30)
2. "程序员如何用 Excel 监控水电预算" (STEPPS: 24/30)
3. "水电验收的 7 个关键节点，漏一个就完蛋" (STEPPS: 23/30)
```

**Phase 2 追问**: "你觉得哪个方向最能体现你的独特性？"

**用户**: "第二个吧，用 Excel 这个很程序员"

**Phase 2 深化**: "很好。那具体来说，你的 Excel 和普通表格有什么不同？"

**用户**: "我会自动抓取合同里的项目，和实际报价比对，然后标记异常"

**Phase 2 洞察发现**: 
```
你的独特定位：不是"教水电知识"，而是"程序员的预算监控系统"
悖论：大多数人追求专业知识，你用工具替代经验
```

**Phase 3-5**: ...继续执行 ...

**Final**: 输出完整发布方案

## 💡 Tips for Best Results

1. **越模糊越好**: 初期不用想得那么细，"随便聊聊装修"也能开始
2. **随时打断**: 不想某个环节了就直说"跳过这个"或"换方向"
3. **给真实反馈**: "这段太 AI 了""这句很奇怪"能帮助系统更好调整
4. **善用反问**: 当你不确定时，让 skill 问你问题比强行回答更有效
